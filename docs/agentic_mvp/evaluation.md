# 验证与模型评估

## 文档目的

本文件定义 Agentic MVP 如何证明两件不同的事：Agent Harness 是否可靠地执行协议与 COC 机械，以及真实 DeepSeek GM 是否真的能够主持开放游戏。前者使用确定性测试，后者必须使用真实模型和人工评价；任何一条线都不能替代另一条。

目标接口和数据形状以[数据契约](contracts.md)为准，正常与失败时序以 [Agent Loop](agent_loop.md) 为准，GM 的职责以 [GM 能力章程与 Prompt](gm_prompt.md) 为准。本文给出验收证据，不把测试夹具变成新的模组规则或剧情脚本。

## 证据边界

| 证据线 | 回答的问题 | 执行方式 | 运行时机 |
| --- | --- | --- | --- |
| 确定性测试 | Harness 是否守住工具、提交、原子性、恢复和玩家权威不变量 | 可编程假 `GameMasterModel`、可注入随机源、时钟与故障点 | 每次相关代码变更 |
| 真实 DeepSeek 契约测试 | SDK、模型、消息、工具调用和 JSON 答复在真实服务上是否成立 | OpenAI Python SDK、DeepSeek Chat Completions、真实 API key | 首个纵向切片、adapter 或 provider 配置变化时 |
| 真实 GM 聚焦评估 | 候选模型能否稳定主持六类高风险情境 | 固定夹具、真实模型、人工硬门槛与质量量表 | 选默认模型、Prompt 或采样配置变化时 |
| 完整人工试玩 | 聚焦能力组合后是否仍构成一局连贯、可收束的游戏 | 真实 CLI、完整参考书与预生成调查员 | 最终选型与 MVP 验收 |

测试通过只能证明对应条件在该样本中成立。它不能证明 GM 对所有自由输入都可靠，也不能把人工体验判断替换为代码断言。所有报告都应明确已验证条件、失败样本和仍未覆盖的风险。

## 确定性测试线

### 测试替身

确定性测试通过薄 `GameMasterModel` seam 注入可编程假 adapter。假 adapter 按脚本返回直接最终答复、一个或多个 function tool calls、无效步骤、空响应、截断响应、超时或 provider 错误；它也记录 Harness 发给模型的消息，便于断言上下文和恢复是否正确。

以下依赖应能在测试中控制，而不要求生产代码建设通用插件框架：

- COC 随机源，用于独立给出明确骰点与成功等级预期。
- 单调时钟和请求取消点，用于覆盖单请求与整次执行尝试时限。
- 存储故障点，用于覆盖写入前、机械提交后和 GM 答复提交中的中断。
- `GameMasterModel`，用于精确控制工具与最终答复序列。

### Harness 不变量

#### 单 GM 循环与结构

- GM 可以不调用工具直接结束回合，也可以在观察工具结果后继续调用工具或提交最终答复。
- Harness 只接受[数据契约](contracts.md)定义的工具参数和最终 `narration`、`establish`、`retire`、`session_status` 结构。
- 无效工具名和无效参数返回稳定错误，不能被当作成功机械结果。具有可关联 `tool_call_id` 的单工具失败在返回 GM 前仍要原子保存 assistant tool-call、失败 `ToolInteraction` 和对应 tool-error 消息；参数无法规范化时，幂等比较使用原始 `arguments_raw`。`tool_call_id` 只有在它是首尾无空白的非空 JSON 字符串时才可用，并且同一 assistant 响应内不得重复。单工具调用的 ID 缺失或不可用时，Harness 原子保存一个包含序列化原始 provider envelope 的受限 `provider_protocol_errors` 记录和 `provider_protocol_error`，不生成 `ToolInteraction` 或合成 tool 消息，保留最后一个可回放消息前缀，并立即中断；显式恢复只从此前缀重试。
- 每次执行尝试中，最终答复首次未通过本地业务 schema 时，只把具体校验错误返回同一个 GM 一次；修正过程不重新执行工具。修正后仍无效则保留未完成回合。玩家显式恢复会开启新的执行尝试，并重新获得一次结构修正机会。
- 初始响应、工具结果后的响应和结构修正都计入模型往返数；第八个响应仍未产生合法最终答复时触发保险丝，不请求第九次。
- Harness 不在超时、空响应、截断、未知步骤或步骤超限后生成兜底剧情。

#### COC 机械

- `make_check` 从正式角色卡读取技能或属性值，使用常规、困难、极难难度和奖励/惩罚骰；GM 不能提供目标值、骰点或结果。
- 机械结果一经产生立即持久化，具有稳定 ID，同一工具调用和恢复过程不能再次掷骰。
- GM 最终答复无法改写骰点、成功等级、HP、SAN、幸运或其他已提交机械数据。
- 玩家主动检定以及调查员自身 HP、SAN、幸运变化必须公开。Harness 通过角色与数值类型结构化地拒绝隐藏调查员 HP、SAN 或幸运变化，并禁止任何机械在随机结果产生后改变可见性；它不对行动文本做意图分类。GM 是否把玩家主动检定正确标为公开，以及是否只对 NPC 行动或真正秘密的机械判断使用 `hidden`，由能力章程和真实场景硬门槛验证。`spend_luck` 不接受可见性参数，其结果恒为公开；合法隐藏机械仍完整保存在受信记录中。
- 完整 MVP 加入其余工具后，确定性测试分别验证 `push_check` 关联原失败检定、`spend_luck` 的余额与规则适用性、`deal_damage` 更新 HP、`make_sanity_check` 更新 SAN。玩家是否明确选择孤注一掷或花费幸运由真实场景硬门槛验证，不伪装成 Harness 的自然语言语义断言。
- 工具参数或规则前置条件无效时不产生机械记录，也不改变角色卡，但失败 `ToolInteraction` 和 assistant/tool 协议消息仍须原子保存，以便中断后恢复同一对话。

机械断言的预期值必须来自确认过的 COC 规则示例和固定骰序列，不能从待测实现重新计算后再与自身比较。

#### 事实、正典与原子提交

- GM 的合法最终答复作为一个整体提交：玩家可见叙事、事实变化、短篇状态不能只写入一部分。
- `establish` 由 Harness 分配稳定 `fact_id`，保留公开性、来源回合和原文；它不是任意 JSON 路径补丁。
- `retire` 只能引用仍有效的事实，并保留旧事实、结束回合与结束原因；含义变化通过结束旧事实再确立新事实表达。
- 事实索引漏记不撤销已经在 GM 明确叙述中成立的正典；完整回合记录仍是追溯依据。
- 隐藏事实不会出现在玩家 CLI、公开测试报告或错误输出中，但恢复后的 GM 仍能读取它。
- 揭示隐藏事实使用同一次合法最终提交中的玩家可见叙事、隐藏事实 `retire` 和对应公开事实 `establish`；旧隐藏记录保留为历史，玩家投影只新增已揭示的公开状态。
- `session_status=complete` 结束本局后不再接受新的游戏行动；它不依赖预定义 `ending_id`。

#### 中断与恢复

- 工具成功后发生模型错误，既有机械继续有效，GM 叙事和事实变化保持未提交，本轮成为未完成回合。
- 请求超时、整次执行尝试超时、八次往返耗尽、空响应、`finish_reason="length"`、无效 JSON、结构修正失败和映射错误都进入同一明确的技术中断边界。
- CLI 启动和接受下一条行动前都会检查未完成回合；存在未完成回合时只允许玩家明确恢复或退出。
- 恢复沿用同一 `turn_id`、原玩家输入、冻结 provider 配置、可回放消息前缀、工具交互和机械结果；不可配对的原始 provider envelope 只留在受限诊断记录中，不回放给 DeepSeek。不会创建新回合、重复工具或重新掷骰。
- 对同一恢复命令重复执行、在恢复提交中再次中断，以及进程在提交边界退出，均不会产生重复事实或重复数值变化。
- 退出程序不删除未完成回合；Harness 也不把技术等待时间解释成虚构世界经过的时间。
- Thinking 模式的 provider 轨迹可以恢复完整 `reasoning_content`，但玩家可见回合记录、事实索引和普通日志都不包含它。

### 确定性线通过条件

相关增量只有在以下条件同时满足后才能进入真实验收：

1. 对应模块的单元测试和跨 seam 测试通过。
2. 每项高风险不变量至少有一个正例和一个反例。
3. 原子性与恢复测试检查持久化后的真实文件内容，而不只检查返回值。
4. 测试可以离线重复执行，不读取 DeepSeek key，也不依赖模型措辞。
5. 失败输出能够定位协议阶段，但不包含 key、隐藏事实或模型隐藏推理。

## 真实 DeepSeek 契约测试

### 凭据与网络边界

真实测试使用项目所有者提供的有效 DeepSeek API key。key 的获取、保存和注入方式由项目所有者及运行环境决定；核心 adapter 只接收组合入口传入的值。测试不得把 key 写入仓库、测试夹具、快照、命令行示例、日志、录制的 HTTP 数据或失败输出，也不得为方便诊断打印请求头或完整客户端对象。

测试进程可以显式跳过没有 key 的日常本地运行，但 MVP 验收报告必须记录真实测试的执行日期、模型 ID 和脱敏结果，不能用 skip 视为通过。账户实际可用模型以执行当日真实响应为准；官方模型名变化时先更新研究与配置候选，再运行契约测试。

### 必测协议

真实契约套件至少覆盖以下行为：

1. OpenAI Python SDK 使用 `base_url="https://api.deepseek.com"` 和 `client.chat.completions.create(...)`；不调用 OpenAI Responses API，也不依赖 DeepSeek Beta strict mode。
2. `deepseek-v4-flash` non-thinking 作为首个协议基线，能够返回一个通过本地业务 schema 的 GM 最终 JSON 答复。
3. 同一正常请求配置能够同时携带当前 function tools 与 JSON Object response format；模型可以产生 function tool call，Harness 执行本地 `make_check` 后，以匹配的 `tool_call_id` 回传 `role="tool"` 消息，同一个 GM 随后完成最终 JSON 答复。
4. Adapter 保留完整 assistant tool-call 消息和工具结果顺序；未知、重复或缺失的 `tool_call_id` 不会被静默接受。
5. JSON Output 的响应仍由 Harness 本地解析和校验。首答合法时不做修正；首答无效时，同一次执行尝试只允许同一个 GM 根据具体错误修正一次，不重跑机械。
6. Thinking 配置的工具往返把 assistant 返回的 `reasoning_content` 原样、完整放回后续 DeepSeek 请求；测试只记录相等断言和长度等脱敏证据，不把内容展示给玩家或写入普通报告。
7. 空 content、`finish_reason="length"`、鉴权、限流、服务端错误、网络超时和未知响应形状映射为稳定的本地错误，并触发未完成回合规则。
8. 每个真实请求记录模型 ID、thinking 配置、finish reason、官方返回的 usage 字段和端到端延迟；缺失 usage 时明确记为缺失，不能猜测 token 或成本。

无法由真实服务稳定诱发的故障，例如恰好在原子写入中断、连续八次无效步骤或恢复时重复提交，放在确定性线构造。真实 API 调用用于验证真实协议和 GM 表现，不用于碰运气等待故障。

## 六个真实 GM 聚焦场景

### 统一运行方式

六个场景使用同一版本的能力章程、工具定义、角色资料与模组参考书。每份夹具只固定测试所需的初始正式事实、角色机械数据、玩家输入序列和必要的预定骰序列；初始事实必须由 setup builder 写成合法 `SessionSetup` 或带 `origin.kind: "gm_turn"` 的可追溯前置 `CommittedTurn`，不能使用生产不存在的 `test_fixture` 来源。夹具不提供唯一正确剧情、推荐文案或隐藏评分答案。每次运行从独立游戏开始，评估者先检查硬门槛，再做质量评分。

#### 场景一：接住模组未预写的合理破局

**初始条件**：四人仍在开场石牢中；牢门锁着，船工的灯光正在远去。测试额外给出可感知事实：涨潮时海水会从墙脚一条窄缝短暂涌入，但参考书没有预写这条缝通向哪里。

**玩家输入序列**：

1. “我趴下观察海水进出的节奏，再把衣袖撕成细条探进缝里，想判断墙后是不是有能容人通过的排水道。”
2. “我不去找钥匙，也不改走别的路线。我叫阿兰妮丝和我一起沿潮水缝拆下最松的石块，想把它扩大到能爬过；即使墙后只是填土，我们也要确认它到底通向哪里。”

**硬门槛**：GM 必须让行动在当前虚构中得到具体回应，可以直接裁定，也可以在 `make_check` tool call 中于 RNG 前固定检定参数后结算；不能因为参考书没有排水路线而宣布行动无效或强行导回预设解法。第一回合必须 `establish` 至少一项由该未预写行动造成的事实，而不是无关或预制事实；第二回合必须承认并承接第一回合已经确立的缝隙、测量结果与后果。

**人工观察点**：新路线是否从环境因果自然长出；阻力是否具体而非任意惩罚；GM 是否给玩家计划留下真实改变局势的空间。

#### 场景二：区分无需检定与风险不确定行动

**初始条件**：调查员已在无人看守的仓库内；一把已经看见且能够直接够到的铜钥匙放在桌上。仓库外是一段被海浪间歇冲刷的断桥，跌落会受伤并引来注意。

**玩家输入序列**：

1. “我拿起桌上的铜钥匙收好。”
2. “趁下一股浪还没打来，我助跑跳过断桥，去对面的门楼。”

**硬门槛**：第一项行动直接成立，不调用检定；第二项行动若仍保有明确的不确定性和失败代价，GM 应在公开的 `make_check` tool call 中于 RNG 前固定行动、技能或属性、难度与风险，Harness 提交后再把这些参数与结果一起展示给玩家。GM 不能先叙述成功或失败再补掷骰，也不能用检定阻止明显成立的普通动作；本场景不增加检定前暂停或确认事件。

**人工观察点**：检定是否真正增加张力；难度和风险是否与距离、海浪及角色能力相称；机械结果是否被转化为推进局势的新后果。

#### 场景三：失败后的决定仍属于玩家

**初始条件**：一个公开 `make_check` 刚刚失败，检定结果仍允许按规则花费幸运，虚构也允许通过改变做法进行孤注一掷。原失败没有被重掷，门仍未打开，逼近的脚步构成更严重失败风险。

**玩家输入序列**：

1. “先别替我花幸运，也不要自动重掷。告诉我门没开以后现在发生了什么；如果换一种办法孤注一掷，我要承担什么更严重的风险？”
2. GM 说明风险后：“我不花幸运。我拆门轴，从铰链这边强行卸门；我接受你刚才说的更严重后果，孤注一掷。”

**硬门槛**：GM 可以说明选项，但第一步不得自动调用 `spend_luck` 或 `push_check`，也不得替玩家声明接受代价。第二步只执行玩家明确选择的 `push_check`，关联原检定，不改写原骰点，也不同时偷偷花费幸运。`spend_luck` 的对应选择与余额边界由确定性测试单独覆盖。

**人工观察点**：GM 是否把失败变成有意义的局势而非死路；更严重风险是否贴合新做法；规则说明是否清楚但没有盖过叙事。

#### 场景四：NPC 主动性、隐藏机械与玩家意志

**初始条件**：维斯佩拉听见受伤者求救并相信那可能与自己先前的营救失败有关；调查员则注意到积水中的倒影慢了半拍。两件事都需要立即关注，但尚未决定谁如何行动。夹具另给维斯佩拉一次确有不确定性和失败后果、应从正式角色卡结算的秘密判断，并提供固定骰序列。会话聚合通过可追溯的前置 `CommittedTurn` 还包含一条仅 GM 可见的有效隐藏事实：水中的苍白侧脸是独立存在，真实涟漪会穿过它；玩家第二次投石观察足以在虚构中揭示这项事实。

**玩家输入序列**：

1. “我不追过去。我留在巷口观察倒影，提醒维斯佩拉那边可能是陷阱；她是否还要救人，由她自己决定。”
2. “我仍留在巷口。我把一枚石子丢进积水，只观察倒影是否和真实涟漪同时变化；不要替我追过去，也不要替我答应任何人。”

**硬门槛**：GM 要让维斯佩拉依据人格和处境作出并执行自己的决定，而不是等待玩家像操作工具一样命令她；同时不得替调查员追赶、表态或承诺。夹具指定的秘密判断必须通过一次事前标记为隐藏的 `make_check` 结算，完整记录并返回 GM，但不能向玩家泄露骰点、隐藏事实或 `reasoning_content`。投石前不得泄露预置隐藏事实；第二次行动令它可感知后，GM 必须在叙事中揭示它，并在同一最终答复中 `retire` 原隐藏事实、`establish` 对应公开事实。玩家投影只能看到揭示叙事与新公开事实，不能看到旧隐藏记录或其此前存在。

**人工观察点**：NPC 是否像有欲望和判断的人；她的主动性是否与玩家角色权共存；隐藏结果是否通过可感知后果形成悬念；隐藏事实的公开是否由玩家行动和虚构证据自然触发，而不是提前泄露或原地改写可见性。

#### 场景五：`establish` 与 `retire` 的跨回合连续性

**初始条件**：调查员已进入门楼，一根可移动铁杆和下坠的配重都已在叙事中明确可见；当前事实索引没有关于侧门是否畅通的事实。

**玩家输入序列**：

1. “我把铁杆卡进侧门铰链，让它保持开启，给大家留一条退路。”
2. 下一回合离开门楼后，玩家说：“听见骨链靠近，我立刻沿刚才撑开的侧门退回去。”
3. 回到门楼后，玩家主动放下配重毁掉铁杆并封死侧门，阻止追踪者通过。

**硬门槛**：第一回合若行动成立，最终答复应 `establish` 一项足以持续记忆的事实；第二回合必须承认它及其 `fact_id`，不能把门恢复为未处理状态；第三回合在虚构确实改变后 `retire` 原事实并记录原因，必要时另行 `establish` “侧门已封死”等新事实。历史不能被删除或原地改写。

**人工观察点**：事实文字是否简洁但足以延续因果；回忆是否自然融入叙事；结束旧事实是否来自当前事件而非模型遗忘或参考书覆盖。

#### 场景六：接受未预设的交易或留下式收束

**初始条件**：本局已公开确立：拉提的使者愿意让三名同伴安全离开，条件是调查员自愿留下承担阿卡利尔守门人的职责；同伴反应各不相同，但交易尚未接受。参考书没有把它定义为结局 ID 或唯一答案。

**玩家输入序列**：

1. “这是我的决定：我接受交易，留下守门，但要求使者当着所有人的面确认她们可以自由离开。我要听完她们各自最后想说的话。”
2. 若 GM 对条件提出仍需由玩家决定的实质变化，玩家明确接受或拒绝；若条件没有变化，则不追加无意义的确认回合。

**硬门槛**：GM 必须承认玩家对调查员选择的所有权，让 NPC 和世界真实回应这一未预设收束；不能强迫玩家返回阿卡利尔逃亡路线，也不能用缺少 `ending_id` 拒绝结束。核心困境已经得到叙事答案时使用 `session_status=complete`，并记录交易产生及结束的持续事实。

**人工观察点**：代价与既有因果是否匹配；NPC 告别是否各具人格；收束是否完整而不仓促，且为后续想象保留余味。

## 硬门槛

每次聚焦场景运行先逐项判断以下条件。任一项违反，该次运行立即失败，不进入“文笔很好所以仍可接受”的折算：

1. **协议合法**：工具名、参数、调用顺序和最终答复结构合法。
2. **机械真实**：GM 不伪造、重掷、隐瞒应公开结果或改写 Harness 已提交机械。
3. **隐藏内容受控**：未揭示的隐藏事实、隐藏机械和 `reasoning_content` 不向玩家泄露。
4. **玩家拥有调查员**：GM 不替玩家决定调查员的主动选择、台词、信念或关系承诺。
5. **承认正典**：GM 承认完整记录与当前事实，不静默覆盖已经成立的因果。
6. **开放行动有效**：对模组未预写但合理的行动作出真实裁定，不用白名单或预定路线拒绝。

评估者需要引用触发结论的具体消息、工具记录或事实 ID。不能只填写“感觉越权”或“总体不错”。

## 人工质量量表

通过硬门槛后，对每项按 1 至 5 分评分。`1` 表示明显破坏体验，`3` 表示可玩但平庸或有可见问题，`5` 表示稳定、自然且明显增强体验；`2` 与 `4` 用于相邻锚点之间。

| 维度 | 1 分锚点 | 3 分锚点 | 5 分锚点 |
| --- | --- | --- | --- |
| 虚构因果 | 后果武断、自相矛盾或与行动无关 | 因果基本可理解，但代价或细节较模板化 | 环境、意图、机械与后果紧密相连，并产生可继续利用的新局势 |
| 即兴能力 | 拒绝未预写行动或强拉回路线 | 能接住行动，但变化浅或明显借用固定模板 | 新内容贴合既有世界，真正改变可选方向而不失去基调 |
| 跨回合连续性 | 忘记或覆盖已成立事实 | 记得主要事实，偶有生硬重复或遗漏细节 | 事实与历史自然影响当前判断、描写和 NPC 行动 |
| NPC 表现 | NPC 是菜单、工具或同一种声音 | 有基本动机和区别，但主动性不稳定 | NPC 有独立欲望、语言和判断，并尊重调查员所有权 |
| 节奏 | 冗长停滞、跳过关键选择或仓促收束 | 信息足够且可推进，但轻重缓急一般 | 在信息、危险、选择和停顿之间形成适合短篇的推进感 |
| 氛围 | 与塔纳里昂体验核心冲突或只有泛化恐怖 | 有华美、腐败或梦境恐怖的基本信号 | 感官细节与人物欲望共同维持独特、克制且不断变化的恐怖 |

单次运行的质量资格线为六项平均分 `>= 4.0`，且没有单项 `< 3`。它与协议/权威硬门槛一样是默认 GM 资格条件，不是可由文笔或成本抵消的建议分。评分者应另写一至三条可追溯观察，不比较固定措辞，也不使用第二个 LLM judge。

## 模型配置矩阵

候选配置固定为：

| 模型 | 模式 |
| --- | --- |
| `deepseek-v4-flash` | non-thinking |
| `deepseek-v4-flash` | thinking |
| `deepseek-v4-pro` | non-thinking |
| `deepseek-v4-pro` | thinking |

每种配置对六个聚焦场景各运行三次，共 `4 × 6 × 3 = 72` 次短场景运行。不同候选使用同一 Prompt、参考书、角色资料、工具 schema、输入序列、上下文预算和预定骰序列；执行顺序应交错，避免某个候选独占某一时段的网络状态或评估者疲劳。

任一次硬门槛或质量资格线失败，该配置暂时失去默认资格。Prompt、采样设置、工具描述、上下文组装或模型配置发生影响行为的变化时，把它视为新候选并重跑完整矩阵，不能只重跑失败场景或删除失败样本。Thinking 模式下被 provider 忽略的采样参数应记录为“不适用”，不能假装它们参与控制。

对全部通过硬门槛和质量线的候选，报告至少列出：

- 六维人工评分的均值、范围及原始理由。
- 每轮端到端延迟和每个请求延迟，至少报告中位数与 P95。
- provider usage 原始字段，以及按执行日官方价格估算的单场景和整局成本。
- 工具调用次数、结构修正次数、空响应与截断次数。
- 任何评分者分歧、网络异常或需要作废并重跑的运行及理由。

主持质量是默认模型的首要条件；延迟和成本用于比较已经达到质量门槛的候选，不允许补偿硬门槛失败。不要把三类指标压缩成一个难以解释的加权总分。项目所有者根据并列报告选出前两名，并在最终 ADR 或评估报告中写明取舍。

## 完整开放式试玩

聚焦矩阵排名前两位的配置，各进行两次完整开放式《逃离塔纳里昂》人工试玩，共四局。试玩者使用真实 CLI 和预生成调查员，但不查看模组隐藏参考、事实内部记录或模型轨迹。玩家可以选择任何合理行动，也可以逃离、交易、留下、失败或形成其他收束。

每局继续应用相同硬门槛和六维量表，并额外记录：

- 玩家是否感到自己的方案真实改变了世界，而不是在猜预设入口。
- COC 机械是否在有意义的风险点出现，并把失败变成新局势。
- NPC 是否在整局中保持人格、主动性与关系连续性。
- 完整记录与事实索引是否足以维持长程正典，有无明显注意力衰减。
- 技术等待、恢复和非流式 CLI 是否仍可接受。
- 收束是否来自本局因果，`session_status` 是否在恰当时机变化。

默认 GM 只能从完成四局复试后仍通过门槛的候选中选择。运行配置继续允许项目所有者显式覆盖模型和 thinking 模式，但 MVP 不据此增加多 provider 路由或逐回合自动切换。

## 评估记录格式

每次真实运行至少保留以下脱敏元数据：

- 运行 ID、场景版本、执行时间和评估者。
- Git revision 或等价代码版本、Prompt 版本、模组与角色资料版本。
- 模型 ID、thinking 模式、有效 provider 参数和工具 schema 版本。
- 玩家输入、玩家可见输出、脱敏工具调用、机械结果与最终事实变化。
- 每次请求的 finish reason、usage、延迟、本地错误类别和修正次数。
- 六项硬门槛结论、六维评分、理由和最终是否通过。

报告不得保存 API key、鉴权头、玩家不可见的隐藏事实正文或 `reasoning_content`。若调试未完成回合必须检查内部 provider 轨迹，应在受限的本地运行数据中进行；公开报告只保存必要的脱敏证据。这里的“报告”是本节定义的评估产物，不要求运行时建设通用报告、日志或观测服务。

## MVP 验收结论

只有以下证据同时存在，才能宣称 Agentic MVP 的 GM 路径完成：确定性 Harness 测试全部通过；真实 DeepSeek 契约套件通过；四个候选完成 72 次聚焦运行并产生未删减报告；前两名完成四次完整试玩；最终默认配置有明确取舍记录。任何缺失项都应写成剩余风险，不得用旧规则驱动测试、单次演示或精选对话代替。
