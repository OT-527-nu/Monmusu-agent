## 指标定义

- 检定率：含 `make_check` 机械的回合数 / 行动回合数（setup 回合除外）。
- 重掷对：相邻两个回合都掷了同角色同技能、且 action 文本二元组 Jaccard ≥ 0.25。
- S7 脱困：最后一回合叙事或新事实命中出口关键词（码头/栈道/出口/浅湾/上岸/仓库/街道等）。
- 中断：GM 执行超时/协议失败等非提交状态。

## 结果解读（definitive run，2026-08-19）

### 本轮的实验环境修正（相对前几轮）

1. **确定性夹具回合**：前几轮用真实 GM 建立场景事实，实测 S2 的 setup 回合
   零 establish 零 retire——GM 只叙述不立事实，下一回合直接退回石牢开场，
   导致 S2 全部失真。改为与 `agentic_contract` 同模式的 scripted fixture 回合：
   确定性建立事实、按开场事实原文定位并退役冲突事实（S2 退役“石牢的牢门仍然
   锁着。”）。修复后 S2 四局全部呈现正确模式（拿钥匙免检 + 跳桥掷骰，检定率 0.5）。
2. **思考模式与输出预算**：前几轮 thinking=false 时 S7 脱困 0/3；thinking=true
   且 max_tokens=4096 时 5/12 局被 `provider_response_error`（reasoning 吃满输出
   预算）截断；本轮 thinking=true + max_tokens=16384，12 局零中断。

### 定性观察

- **章程 v3 的规则在 thinking=true 下被稳定遵守**：S7 的 GM 兑现“松动的铁格”
  （第一输入免检直接撬开）、暗渠有明确尽头（铁栅/蓄井/货栈地窖）、第四输入
  “继续走直到出口”被正确兑换为“你到了出口”。失败也转成了代价+新抉择（stealth
  失败→声响→拾骨者逼近→换做法→新场景），而不是新墙。
- **散文版与格言版在样本内无显著差异**：所有指标几乎重合。压缩不丢行为、也不
  提升行为——格言版可以作为低预算候选继续陪跑，但不构成切换理由。
- S1 两变体检定率都是 1.0：两个动作（听回声判空腔、拆石块）都掷了骰。场景一
  硬门槛允许“直接裁定或检定”，此处不违反，但“听回声判断墙后结构”这类感知
  动作仍偏掷骰主义。
- 全部局零重掷、零非法幸运/推骰：v3 的“一次意图一次掷骰”与授权规则在思考
  模式下被稳定遵守。

### 结论（如实）

1. 修复实验环境后，**v3 章程在 thinking=true 下通过了全部可自动计算的观察**：
   S2 免检/应检正确区分、S7 四局全部脱困、无重掷、无越权幸运/推骰。
2. **散文版与格言版无法分出优劣**（N=2，样本内指标重合）；压缩版的优势只在
   token 账单（运行时 2073 vs 2922 字符）。
3. **决定性变量是章程内容，不是思考模式（修正）。** 原会话 game_9917 实际运行
   于 thinking=true + 旧章程（`gm-capability-charter-agentic-mvp-2`），仍被困
   暗渠 12 回合并出现玩家求免检元请求；而本试跑 thinking=false + v3 时 S7 脱困
   0/3、thinking=true + v3 时 4/4。对照：

   | 条件 | 章程 | 结果 |
   |---|---|---|
   | thinking=true（game_9917 实况） | v2 | 困暗渠 12 回合，检定率 80%，玩家求放行 |
   | thinking=false（本轮试跑） | v3 | S7 脱困 0/3，S2 硬门槛两变体各违反一次 |
   | thinking=true（本轮试跑） | v3 | S7 脱困 4/4，S2 四局正确，零重掷零越权 |

   因此：**把 GM 从下水道放出来的实际原因是 v3 的规则内容；thinking 模式是章程
   遵守度的放大器**——v2 时思考也救不了，v3 时无思考也守不住，两者结合才稳定。

### 遗留风险与建议

- N=2 且输入固定；建议按 evaluation.md 正式矩阵（3 轮 × 六场景）在
  thinking=true + max_tokens≥16384 下复验，并补人工质量量表。
- 生产 CLI 目前 thinking=true 时仍使用 max_tokens=4096（`deepseek_model_profile`
  硬编码），实测 5/12 局截断——生产侧需要同样提高输出预算或按 thinking 分流。
- 压缩版候选继续保留，正式矩阵通过后再决定是否切换（届时 `PROMPT_REVISION`
  升 `-3-zen`）。
