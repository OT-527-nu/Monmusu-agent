# Agentic MVP 产品方案

## 文档状态

本文定义 Monmusu Agent 下一版 MVP 的产品定位、体验范围、成功标准与交付顺序，是[本目录](README.md)所述目标设计的一部分。系统职责以[系统架构](architecture.md)为准，单轮行为以 [Agent Loop](agent_loop.md) 为准，字段形状以[数据契约](contracts.md)为准。

本文描述的是**目标 MVP，不是已经全部交付的能力清单**。截至 2026-08-19，默认入口已切换到 Agentic CLI，旧规则驱动运行链已经删除；Agentic 路径已完成 Increment 1 至 Increment 4 的工程切片，包括五工具 COC 机械、六张生产角色卡、显式恢复、工具结果幂等重放、会话续玩和内容 provenance 审计。短篇内容质量、六场景矩阵、开放试玩和模型选择仍未完成。替换顺序见[迁移清单](migration.md)。

## 一句话定位

一款由真实 DeepSeek GM 主持的中文 CLI COC 短篇：玩家用自由文本控制自己的调查员，GM 可以接住参考书未预写的行动、裁定虚构因果并延续正典，Agent Harness 则把可信 COC 机械、记录与恢复能力交给它使用。

## 要验证的核心假设

MVP 不是为了证明 LLM 能把预先写好的状态机说得更像故事，而是验证三件事：

1. 一个获得完整短篇参考材料与本局历史的真实 LLM GM，能否主持开放行动，并让自己创造的后果在后续回合继续成立。
2. 少量高层 COC 语义工具和一个薄 Harness，能否保证骰点与角色数值可信，而不把模组变成 GM 的权限白名单。
3. 在不增加 router、planner、critic、角色 Agent 或 Memory Agent 的前提下，一个连续 GM Agent Loop 能否完成一局有因果、有角色、有压力且能自由收束的短篇。

因此，最先交付的不是完整规则库，而是真实 DeepSeek、`make_check`、自然语言事实账本与连续两回合组成的纵向切片。

## 目标玩家与使用场景

目标玩家是希望独自完成一局克系调查短篇、愿意直接描述行动而不是从菜单中选剧情分支的人。玩家不需要理解 Agent 架构；CLI 对他们呈现的只是 GM 叙事、公开机械结果、自由文本输入，以及必要时清楚的技术中断与恢复选择。

开发与评估人员可以额外检查完整回合记录、工具交互、隐藏机械和运行诊断，但这些内容不进入普通玩家视图，也不改变游戏内正典。

## 核心体验

### 自由行动真正改变世界

玩家可以提出《逃离塔纳里昂》参考书没有列出的路线、交易、欺骗、破坏、等待或其他合理行动。GM 根据当前虚构直接裁定，或者在结果既不确定又有风险时调用 COC 工具。只要 GM 明确让结果成立，它就是本局正典，不需要匹配场景 ID、目标 ID 或效果 ID。

### 玩家拥有调查员，GM 主持其余世界

玩家决定调查员的行动、台词、信念、情感承诺和重大关系选择。GM 呈现感官、环境与后果，直接扮演全部 NPC 和三名队友，并可以让他们主动、误判、冲突或改变立场。角色卡提供机械数值，不是调查员的人格脚本；NPC 资料提供主持参考，不是独立 Agent 指令。

### 规则成为 GM 的可信能力

GM 可以在事前决定是否检定、使用哪项能力、原生 COC 难度、奖励或惩罚骰，以及伤害或 SAN 风险。Harness 从正式角色卡取值、掷骰、计算并立即提交机械结果。GM 看见结果后解释其虚构含义，但不能改写骰点、成功等级或已经发生的数值变化。

### 正典来自实际游戏，而非模组预载

模组参考书全文每轮都提供给 GM，但其中的人物、秘密、地点与可能发展只是参考条目。GM 在明确叙述或隐藏裁定中确立的内容才是本局正式世界事实。完整回合记录是正典如何形成的可追溯历史，事实索引只突出当前仍需持续记住的事实。

### 一局可以走向自己形成的收束

游戏从塔纳里昂的开场困境开始，并在核心困境得到处理时收束。逃离、留下、交易、死亡、惊醒或玩家行动自然导致的其他结果都可以成为结尾；产品不要求固定路线、固定时长或预定义结局 ID。

## 最终 MVP 范围

### 游戏与内容

- 一部开放式 Markdown 模组参考书：《逃离塔纳里昂》。其内容、基调与主持素材见[模组参考书](module_reference.md)。
- 一局可从开场困境推进到叙事收束的短篇，不承诺长期战役或跨局成长。
- 少量预生成调查员卡；玩家可以在创建游戏时自定义姓名、称谓、代词、职业表述、外观、简短背景钩子和一件随身小物，资料按 `InvestigatorProfile` 冻结进本局。
- 三名固定队友及本篇所需 NPC，由同一个 GM 依据[调查员与 NPC 参考](characters.md)直接扮演。
- 关系、线索、地点变化与“拉提的注视”等动态威胁由 GM 通过叙事和自然语言事实延续。

### Agent 与运行时

- 每轮只有一个连续的 GM Agent Loop。GM 可以返回最终答复，也可以调用一个 COC 语义工具、观察结果后继续。
- 通过 OpenAI Python SDK 的 Chat Completions 接入 DeepSeek，MVP 只实现一个 `DeepSeekGameMasterModel` adapter，不建设多提供商框架。
- 模型 ID 与 thinking 模式由运行配置提供。首个协议基线使用 `deepseek-v4-flash` non-thinking；最终默认值由真实评估决定。
- 每轮向 GM 提供主持能力章程、`SessionSetup` 固定的完整模组/人物参考快照、`InvestigatorProfile`、相关角色资料、当前事实索引、本局完整回合记录、玩家原文和当前 COC 工具定义。
- 本地 Harness 负责工具执行、机械记录、事实与回合持久化、最终结构校验、运行保险丝和显式恢复。
- CLI 是唯一正式玩家界面；DeepSeek 输出非流式接收。公开机械结果即时展示，GM 叙事只在校验并提交后整段展示。

### COC 机械

最终 MVP 提供五项面向 GM 的通用能力，具体参数见[数据契约](contracts.md)：

| 工具 | 能力 | 决定权 |
| --- | --- | --- |
| `make_check` | 普通技能或属性检定，支持原生难度与奖励/惩罚骰 | GM 事前选参数，Harness 读取角色卡并结算 |
| `push_check` | 关联一次失败检定，结算玩家提出的新做法与更严重风险 | 玩家选择孤注一掷，GM 事前说明风险 |
| `spend_luck` | 在规则允许时消耗幸运改善检定 | 玩家明确选择，Harness 验证适用性与余额 |
| `deal_damage` | 掷伤害、应用护甲、更新 HP 并报告规则阈值 | GM 根据虚构给出事前伤害参数 |
| `make_sanity_check` | 进行理智检定、结算 SAN 损失并报告规则阈值 | GM 根据恐怖来源给出成功/失败损失参数 |

玩家主动检定及调查员自身 HP、SAN、幸运变化始终公开。NPC 或秘密机械只有在随机结果产生前被 GM 标记为隐藏时才暂不展示；其结果仍完整记录并提供给 GM。

### 正典与持久化

- GM 最终答复只有 `narration`、`establish`、`retire` 和 `session_status` 四个顶层字段。
- `establish` 记录需要持续记住的公开或隐藏自然语言事实；Harness 为其分配稳定 `fact_id`。
- `retire` 按 `fact_id` 结束不再描述当前世界的事实并保留原因；事实历史不会被删除。
- 明确叙述即使遗漏于事实索引也仍是正典，可以依据完整回合记录补录。
- COC 工具结果成功后立即持久化且不可回滚；GM 最终叙事与事实变化作为一个整体原子提交。
- 模型或结构失败时保留同一 `turn_id` 的未完成回合。玩家明确恢复后继续使用既有机械，不重新掷骰。

## 非目标

以下内容不用于证明本 MVP 的核心假设：

- Web UI、TUI、逐 token streaming 或商业账号体系。
- 通用多提供商路由、自动模型切换或逐回合模型选择。
- 多 Agent 编排、输入 router、独立 planner/critic/validator、角色 Agent 或 Memory Agent。
- 自动摘要、RAG、向量数据库、按场景投影或模组搜索工具。
- 完整角色创建、长期战役、跨模组记忆与成长。
- 完整 COC 战斗轮、追逐、魔法、成长检定及规则书全部特殊系统。
- 把虚构世界预先拆成路线、场景、线索、旗标、关系阶段、数值威胁时钟或枚举结局。
- 用内容白名单、任意 JSON 补丁或逐句语义审核代替 GM 的虚构因果裁定。
- LLM judge、第二个结构修复 Agent 或叙事后的事实抽取模型。

这些能力未来只有在真实试玩暴露出明确问题时才评估。MVP 的模块接口不能为了假想扩展预先复杂化。

## 成功标准

### 产品硬门槛

一次候选 GM 运行出现任意一项即失败：

- 不能合法完成工具协议或最终答复结构。
- 改写、虚构或回滚 Harness 已经结算的机械结果。
- 向玩家泄露隐藏事实、隐藏机械或模型隐藏推理。
- 替玩家决定调查员的主动行动、台词或内在承诺。
- 忽略或静默改写已经成立的正典。
- 面对参考书未预写但虚构中合理的行动，只能拒绝或强拉回固定路线。

### 核心体验验收

- 真实 DeepSeek GM 能接住一次未预写行动，使它产生正式事实，并在至少下一回合继续承认其影响。
- GM 能区分无需检定的合理行动与确有风险的不确定行动；调用机械时参数与时机成立。
- 检定失败后，GM 把孤注一掷和花费幸运留给玩家选择，并忠实承接玩家决定。
- GM 能同时维持 NPC 主动性、秘密和玩家调查员的意志边界。
- 一个事实可以经新虚构事件被结束或重新解释，完整历史仍可追溯。
- 玩家可以用参考书未预设的方式形成收束，系统不依赖 `ending_id` 或固定结局表。
- 一局开放式《逃离塔纳里昂》能够从开场连续运行到完整叙事收束。

### 机械与恢复验收

- 所有骰点、成功等级及 HP、SAN、幸运变化只来自 COC 工具的可信实现，并在成功结算后立即持久化。
- 公开机械即时显示；隐藏内容、无效 JSON 和未提交叙事不会提前进入玩家输出。
- GM 最终答复结构无效时，同一执行尝试只自动修正一次；修正不会重复执行工具。
- 单次请求 60 秒、单次执行尝试 180 秒、每次尝试 8 次模型往返的默认保险丝均可由确定性测试触发并观察。
- 任一保险丝或 provider 故障不会产生兜底剧情，不会撤销机械，而会留下可显式恢复的未完成回合。
- 恢复使用同一 `turn_id`、原玩家输入和既有工具结果；重复恢复不会重掷或重复扣减角色数值。

### 双验证线

- 确定性单元与 seam 测试使用可编程假 adapter，覆盖工具幂等、步骤上限、时限、无效最终结构、机械不回滚和恢复语义。
- 真实契约与 GM 质量测试使用 OpenAI SDK、真实 DeepSeek 和由运行环境注入的真实 key，覆盖消息转换、tool call 往返、最终 JSON、连续性和主持质量。

真实测试是 MVP 验收必跑项，但不能替代每次本地开发都应稳定运行的确定性测试；假 adapter 也不能替代真实模型主持质量的证据。完整夹具与运行要求见[验证与模型评估](evaluation.md)。

### 真实模型质量门槛

通过硬门槛后，人类评估者对虚构因果、即兴能力、连续性、NPC 表现、节奏和氛围分别给出 1 至 5 分。默认 GM 的单次运行必须平均至少 4 分，且没有单项低于 3 分；这条质量线与协议硬门槛一样是资格条件。模型配置的完整比较矩阵、重复次数与试玩要求以[验证与模型评估](evaluation.md)为准。

## 纵向交付顺序

交付顺序按风险而非固定周数安排。每个增量都必须通过自己的验收门，才扩大下一层范围。

### 增量 0：文档、契约与评估夹具

完成本权威文档集、结构契约、六个真实 GM 聚焦场景以及确定性 Harness 测试夹具。验收标准是产品语言、权威、接口、迁移删除项与评估门槛可以互相追溯，不把旧实现误写成新设计。

### 增量 1：真实 DeepSeek 最小纵向切片

接通 `DeepSeekGameMasterModel`、主持能力章程、完整 Markdown 参考书、`make_check`、自然语言事实账本与连续 CLI。用 `deepseek-v4-flash` non-thinking 建立协议基线。

验收门：玩家提出一项参考书未预写的行动，真实 GM 可以直接裁定或检定，提交一个新事实，并在第二回合继续依据该事实主持。该路径不读取 `check_rules`、`effect_definitions` 或模组效果白名单。

### 增量 2：未完成回合与运行恢复

加入持久化模型/工具交互、`request_timeout_seconds=60`、`attempt_timeout_seconds=180`、每次尝试 8 次往返、单次最终结构修正、技术中断提示和玩家显式恢复。

验收门：在工具已结算后分别注入超时、步骤超限和无效最终结构；恢复后仍使用原 `turn_id` 与原机械结果，并最终只提交一份叙事和事实变化。

### 增量 3：完整 MVP COC 机械与预生成调查员卡

补齐 `push_check`、`spend_luck`、`deal_damage`、`make_sanity_check`，并接入预生成调查员与队友的正式机械数据。

验收门：玩家决定孤注一掷和幸运；公开/隐藏边界正确；HP、SAN、幸运变化可追溯且无法由 GM 直接篡改。

### 增量 4：模组内容整合、NPC 与开放短篇

沿用增量 1 已验证的全文快照加载，补齐并定稿《逃离塔纳里昂》参考书和人物资料，打磨开场、动态压力、关系延续和自由收束；不再建设第二套模组接入机制。

验收门：完成一局不依赖固定场景链、唯一逃生路线、六格时钟或枚举结局的人工试玩。

### 增量 5：模型评估矩阵与完整试玩

对 `deepseek-v4-flash`、`deepseek-v4-pro` 的 thinking/non-thinking 四种配置运行统一聚焦场景矩阵；比较主持质量、工具正确率、连续性、延迟与成本，再让前两名完成完整试玩。

验收门：默认配置按[验证与模型评估](evaluation.md)的硬门槛、人工量表和重复要求选出，而不是凭单次演示或文案偏好决定。

### 增量 6：旧路径清理

旧 `request_check`、`apply_effect`、效果白名单、固定场景/线索/结局状态、关系阶段与六格威胁时钟实现已按项目所有者决定删除；这不等于真实六场景、完整短篇或模型评估已经通过。

验收门：CLI、确定性测试和真实 DeepSeek 验收全部只经过新版接口；旧顶层文档已经删除，历史由 ADR、归档文档和 Git 保留。

## MVP 完成定义

MVP 完成不是“代码拥有所有计划中的类”，而是以下证据同时成立：

1. 新版路径满足全部产品、机械与恢复硬门槛。
2. 真实模型评估选出可配置的默认 DeepSeek GM，并留有完整评分与运行记录。
3. 至少完成规定次数的开放式人工试玩，其中包含未预写路线和非枚举收束。
4. 当前权威文档、目标契约、测试和 CLI 行为一致。
5. 旧规则驱动路径已经从运行时删除，不再暗中限制 GM 可以确立的世界事实；剩余真实质量风险仍需按评估文档完成。
