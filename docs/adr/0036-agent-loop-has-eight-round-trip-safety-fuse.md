# ADR-036：GM Agent Loop 使用八次模型往返保险丝

- 状态：Accepted
- 日期：2026-07-26
- 决策关系：依赖 [ADR-016](0016-one-continuous-gm-tool-loop.md)、[ADR-025](0025-mechanics-commit-before-atomic-gm-response.md) 与 [ADR-032](0032-one-local-schema-repair-attempt.md)

每次 GM 执行尝试设置可配置的模型往返上限，MVP 初始默认值为八次。一次往返是 Harness 向同一个 GM 发出一次模型请求并收到一次响应；初始响应、工具结果后的继续响应、协议纠错响应和结构修正响应都计入额度，COC 工具在本地的执行本身不计入。这个上限是防止异常循环、无界延迟与费用的运行保险丝，不限制 GM 可以作出的虚构裁定，也不构成工具或事实变化预算。

达到上限时，Harness 不要求 GM 仓促生成结局，也不自行编造兜底叙事。第八次响应若是一个合法工具调用，仍执行并原子保存机械与协议交互，但不发起第九次模型请求，随后把回合保存为可恢复的未完成状态；多工具响应全部不执行并保存逐 ID 协议错误，最终 JSON 则照常校验提交。玩家明确恢复后是同一 `turn_id` 的新执行尝试，重新获得八次往返。默认值可以在真实 DeepSeek 轨迹和试玩表明八次不足或过高后调整，不改变这一安全边界。
